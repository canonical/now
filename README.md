# Overview

The command is a single binary named **now** written in Go with no dependencies outside of the standard library.

The command has the following basic syntax:
```
$ now "<human query>" <path> [<path> ...]
```

To perform its job the command sends a query to an OpenAI-compatible API to generate a script to do the requested task.
The remote model only has access to the query, and the provided paths, which may include wildcards, and the generated script
must solve the requested task as a one-shot operation, without going back to the model again. The query may require reading
the content of the provided paths to be fulfilled, but the agent does not have direct access to the content, so
it must construct the script to access the required content and independently solve the task during the script execution.

After the script is generated by the model, it is then presented on STDOUT for user approval, and the user must then
approve the script by pressing ENTER, or cancel it with CTRL-C. The model is instructed to generate clean, simple, readable
scripts, properly indented, so that the human review is simple.

Here are a few examples:
```
$ now "change the suffix to there" *
mv hello-world.txt hello-there.txt
<user presses enter>
<command executed>
$
```

# Labeled paths

Sometimes it may be useful to separate the provided paths in two or more named sets. For that, use the the following
syntax:
```
$ now "rename 1 similarly to 2" 1: foo/*some* 2: bar/*some*
```

# Using stdin

Arguments may be provided via process stdin by using the classic `-` where the argument is supposed to be injected.

All of these are valid examples:
```
$ now - path
$ now "do something" -
$ now "do something" before - after
```
When paths are provided via stdin they must be on independent lines.

# Configuration

The configuration is loaded from `$HOME/.now` using a simple _key=value_ format:
```
api-url=http://127.0.0.1:11434
api-key=abc...
```

# Execution environment

The provided shell command is run with _busybox_ and confined with _bwrap._ Only the paths explicitly provided on the CLI will
be accessible to busybox, so even if the reviewed script is doing something inadequate, only the specific paths listed can
be affected. If directory names are listed, their full content is accessible to the generated script (not the model).

# External commands

It is possible to allow external commands to be explicitly used via the -w (with) argument:
```
$ now -w curl "fetch with the bearer s3cr3t" http://.../data.txt ./data.txt
```
The ./data.txt parameter is required as it allows the path to be written into. Alternatively, a directory path might also
be used, granting the generated script (not the model) access to its full content.

This mechanims works with arbitrary commands, as long as they support the --help argument. The command names are looked
for in the `$PATH`, and multiple commands may be provided by separating them with a comma. The model may decide not to use
the provided commands, though, as it's entirely up to the model how to best perform the requested task.
