# Preface

This document records the design of the sandboxing subsystem of
**now**: the grant flags, the bwrap argument mapping, the procfs
probe, and the package boundaries. If your task touches confinement,
grants, or bwrap integration, this document is relevant; the alias
prelude and busybox internals are covered by `.kb/engine.md` and
`.kb/busybox.md`.

Read the top-level `.kb/agents.md` file before continuing below.


# Overview

Scripts generated by the model run under **busybox ash** and, when
requested, are confined with **bwrap** (bubblewrap). Confinement is always
opt-in: without it, scripts run unconfined as a normal shell session.
The security model mirrors Unix file permissions: the user grants read
(`-r`), write (`-w`), and implicitly execution of external commands
(`-c`), and the network is unshared unless explicitly granted (`-n`).
The core design goal: the model sees only what the user provides, and the
script touches only what the user grants.


# Important

- Confinement is opt-in and off by default. `-s` alone confines with no
  grants (machinery only). Any `-r`/`-w` grant also turns it on.
- The network is unshared whenever confining. `-n` opts back in. This is
  the exfiltration control: granted data may be read, but cannot leave.
- `-c` implies `-r` on each command's resolved path — but only when
  already confining; `-c` alone never turns confinement on.
- Grants must name existing paths (bwrap cannot bind to a nonexistent
  destination). Missing paths fail at parse time, before any model call.
- The probe runs before script generation: a broken bwrap must not waste
  a model call and a human review. `TestRunSandboxFailsBeforeAPICall`
  pins this ordering (zero API requests on confinement failure).
- Scripts see no `$PATH` inside the sandbox; every command invocation
  resolves through aliases to absolute paths (see _Architecture_).


# Architecture

## Flag semantics

- `-r <path>` — grant readable, repeatable, `=`-form supported.
- `-w <path>` — grant writable (implies readable in bwrap terms; bwrap
  has no write-only bind). Same repetition and `=`-form rules.
- `-c cmd,...` — allow external commands; resolved via `$PATH` at parse
  time, `--help` captured verbatim for the prompt (no truncation, no
  caching). Commands that lack `--help` are accepted with empty help.
  Missing commands are a hard parse error (fail-fast, no model call).
- `-n` — keep the network when confined.
- `-s` — confine even without grants.
- Flags are recognized only before the request; afterwards they are
  arguments. Only one `-` (stdin placeholder) is allowed in total.
- Dropped designs (do not resurrect without discussion): `-x` for
  execute grants (bwrap cannot express execute-only binds — a bound path
  keeps its permission bits, so an execute flag would be a fiction;
  `-x` is reserved in case a future mechanism can express it), combined
  forms like `-rw` (pointless once `-w` implies `-r`), and `-l` local
  mode (replicated `-w /` exactly).

## Why these grants map to bwrap this way

bwrap offers `--ro-bind` (read), `--bind` (read-write), `--dev`, `--tmpfs`
and namespace unsharing. There is no write-only or execute-only bind.
Hence: `-w` implies read; execute is not a first-class grant.

## The busybox applet problem (two independent issues)

1. **Applet preference**: busybox built with `FEATURE_SH_STANDALONE`
   resolves command names against its applet table before `$PATH`. So
   `tar` runs the busybox applet even with real GNU tar installed and
   on `$PATH`. This is a property of the shell, independent of the
   sandbox.
2. **`/proc/self/exe` dependency**: applets re-exec themselves through
   `/proc/self/exe` (NOEXEC applets must re-exec to get clean state).
   Without procfs inside the sandbox, applet dispatch breaks with
   `sh: cat: not found` even though the binary is bound.

These issues are independent: (1) exists unconfined, (2) is
sandbox-specific. The **alias prelude** solves (1): `engine.Run` prepends
`alias <name>=<absolute-path>` lines for every `-c` command before the
script. Every command is aliased uniformly — not only shadowing ones —
because uniformity makes each granted command run exactly the binary
resolved at parse time, and (incidentally) it also gives confined
non-shadowing commands a resolution path, since `$PATH` directories are
not bound inside the sandbox.

The shadow check (`IsBusyboxApplet`, a map built from a hardcoded
applet const) was part of the original conditional prelude. The
alias-everything decision removed its only caller, and both the
function and the const were later deleted entirely when the applet
list became probe-driven — see `.kb/busybox.md`. Reviving a shadow
check against the probed `busybox.Options.Applets` is trivial if a
parse-time "note: tar shadows a busybox applet" hint is ever wanted.

## The procfs probe

Fresh procfs (`--proc`) is preferred: applets re-exec through
`/proc/self/exe`, which needs procfs. But `--proc` fails in restricted
environments (containers whose seccomp blocks the mount) with
`bwrap: Can't mount proc on /newroot/proc: Operation not permitted`.

`sandbox.Probe` resolves this once, before script generation:

1. Run the real Options (actual grants, real bind set) with a trivial
   `busybox true` child under `--proc`.
2. If it fails, classify: only the proc-mount-denial stderr is
   retryable. Any other failure means confinement is impossible and
   errors immediately (the original error is preserved — retrying with
   a different proc form would be pointless and mask the cause).
3. Retry once with `--ro-bind /proc /proc` (host procfs, read-only).
   This works wherever bwrap works, but exposes the host's process
   list to the script — an accepted trade-off, recorded here.

The result (`sandbox.Bwrap{Path, HostProc}`) is stored back into
`Options.Bwrap` and reused; `Probe` short-circuits if already set.
Tests cover both proc forms deterministically via a fake bwrap
(`ok`/`denied`/`broken` behaviors, env-var-delivered messages to dodge
apostrophe quoting), because exactly one of the two paths is reachable
in any given environment.

`--ro-bind /proc/self /proc/self` does **not** work: bwrap resolves bind
sources at setup time from its own perspective, so it would snapshot
bwrap's PID dir, not the child's. Per-reader `/proc/self` magic lives in
procfs itself and does not survive a bind.

## Confinement machinery (implicit grants)

Inside the sandbox, bwrap binds read-only, with no user data content:

- The busybox binary (the confined command) and the `-c` binaries
  (via the readable grants the engine adds).
- `/lib`, `/lib64`, `/usr/lib`, `/usr/lib/x86_64-linux-gnu` and
  `/etc/ld.so.cache` — existence-checked, so only present ones are bound.
- `--dev /dev` for devices, `--tmpfs /tmp` for scratch space,
  `--unshare-all` for namespaces (`--share-net` when `-n`).

Rejected earlier: a generated `/bin` directory of applet symlinks bound
at `/bin` with `PATH=/bin` — it worked (busybox re-execs applets fine
through real PATH entries), but it left artifacts (temp dirs, cleanup
funcs) and was replaced by the procfs probe, which keeps applets
working through `/proc/self/exe` re-exec as busybox intends.

## Package boundaries

- `internal/busybox` — resolves the busybox binary and captures its
  applet list (`--list`); the applet list is probed from the installed
  build, not hardcoded. See `.kb/busybox.md`.
- `internal/sandbox` — mechanical confinement: `Options` (grants +
  probe result), `Probe`, `Args`. It never decides whether confinement
  should happen (the caller does) and never executes anything.
- `sandbox.Args(opts, cmdpath, cmdargs...) ([]string, error)` returns the
  complete argument vector: `args[0]` is the bwrap binary, the vector
  ends in `-- <cmdpath> <cmdargs...>`. Binding and exec of the confined
  command are paired inside, so callers cannot pass one without the
  other. Empty `Options.Bwrap` is a hard error, not a silent
  misconfiguration.
- `internal/engine` — builds the alias prelude, executes via
  `exec.CommandContext` so context cancellation kills the process tree,
  and consumes the busybox path the CLI probed.
- `internal/cli` — parses flags, probes busybox first, computes whether
  confinement is on (`-s || -r || -w`), assembles grants (adding `-c`
  paths when confining), probes confinement before `engine.Generate`,
  then runs.
- The prompt does not mention grants — listing them would bias the
  model toward touching paths it would otherwise ignore.
- Arguments get no implicit grants: their meaning is defined by the
  request and the model, not by the filesystem.
